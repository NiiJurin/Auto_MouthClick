# Mouse Macro NEW 画面なし仕様書

## 目的

Mouse Macro NEW は、マウス操作を記録し、あとから単体または再生リストとして繰り返し実行できるデスクトップツールである。

売り物としての方向性は、作業自動化に慣れていない人でも「録る、直す、再生する」が迷わずできること。高度な情報を常時表示するより、操作直前に必要な情報だけ出す。

## 想定ユーザー

- 同じクリック作業を何度も繰り返す人
- マクロやスクリプトには詳しくないが、手作業を減らしたい人
- 座標や待ち時間をあとから少し直したい人
- 複数のマクロを順番に実行したい人

## 基本概念

### マクロ

マクロはクリック列である。

1クリックは次の情報を持つ。

- 前のクリックからの待ち時間
- X座標
- Y座標
- ボタン種別
  - 左クリック
  - 右クリック
  - 中クリック
- クリック後に入力する文字列

古い形式のマクロは読み込めること。古いクリックデータにボタンや文字入力がない場合は、左クリック、入力なしとして扱う。

### 再生リスト

再生リストは、複数のマクロを順番に実行するためのリストである。

各行は次の情報を持つ。

- マクロ名
- そのマクロだけのループ回数

再生リスト全体にもループ回数を設定できる。

## 主要ワークフロー

### 録画

1. ユーザーが録画開始を実行する
2. アプリは現在のマクロを空にして録画状態になる
3. ユーザーのクリックを記録する
4. 右クリック、中クリックも記録する
5. ユーザーが録画停止を実行する
6. アプリはマクロを保存する
7. 保存結果を短く通知する

### 単体再生

1. ユーザーがマクロを選択する
2. ユーザーが単体ループ回数を指定する
3. ユーザーが再生開始を実行する
4. アプリはクリック列を指定回数だけ再生する
5. 完了、停止、エラーを短く通知する

### 再生リスト再生

1. ユーザーがマクロを再生リストに追加する
2. 各マクロ行のループ回数を指定する
3. 必要に応じて行を並べ替える
4. 全体ループ回数を指定する
5. ユーザーが再生リストを再生対象にする
6. ユーザーが再生開始を実行する
7. アプリはリスト順に再生する

### マクロ編集

ユーザーは既存マクロのクリック行を編集できる。

編集できる項目:

- 待ち時間
- ボタン種別
- 座標
- クリック後の入力文字

編集操作:

- 行の上下移動
- 行の複製
- 行の削除
- クリック位置を実際のクリックで指定
- 選択したクリックのみテスト
- 選択したクリックから以降をテスト

## 停止仕様

停止操作は、録画中でも再生中でも最優先で効くこと。

再生中の待ち時間も中断可能であること。停止後に古い待ち時間や古い再生スレッドが次回再生へ残らないこと。

## ショートカット

初期値:

- F1: 録画開始
- F2: 録画停止
- F3: 再生開始
- F4: 全停止
- Esc: 終了

ショートカットは変更できること。

F1などが押されたまま扱いになって次回効かない状態を防ぐため、発火後は押下状態をリセットする。

## 通知とログ

ログは調査用であり、画面の主役ではない。

通常時に必要なのは詳細ログではなく、最後の状態だけである。

状態種別:

- 成功
- 停止
- エラー
- 注意
- 情報

ログにファイルパスは表示しない。

ログは必要な時だけ展開できること。エラー時は詳細を確認できる導線を出す。

## 保存

設定として保存するもの:

- 現在のマクロ名
- 単体ループ回数
- 再生対象
- 再生リスト
- 再生リスト全体ループ回数
- ショートカット

マクロとして保存するもの:

- クリック列
- 将来的にはメモ欄

## UI設計原則

画面は次の順に優先する。

1. 危険な停止操作がすぐ見える
2. 次に押すべき操作が迷わない
3. 選択中のマクロと再生対象がわかる
4. 編集や詳細情報は必要な時だけ出る
5. ログは常時主役にしない

避けること:

- 大きな情報カードを並べすぎる
- 数値や時間を常時強調しすぎる
- 説明文で画面を埋める
- 操作ボタンと状態表示を混ぜすぎる
- 「見せたい情報」のために余白や見た目を壊す

## 画面設計の方向性

推奨する画面構成:

- 上部: 現在の状態、選択中マクロ、再生対象、バージョン
- 左側: 実行操作
- 中央: マクロ一覧と選択中マクロの詳細
- 右側: 再生リスト
- 下部: 折りたたみ式の状態/ログ

情報は大きなカードではなく、表、行、バッジ、ステータスバーで表示する。
